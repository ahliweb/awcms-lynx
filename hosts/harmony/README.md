# HarmonyOS host (ArkTS)

Reference sources for running `apps/mobile/dist/main.lynx.bundle` in a HarmonyOS (NEXT, stage model) app.
Not compiled by this repo's CI — see the STATUS section in [`../README.md`](../README.md).
This is the least-verified of the three hosts: there is no ArkTS toolchain in this repo's environment,
and the Lynx Harmony API surface is documented thinly (see the VERIFY list).

| File | Role |
| --- | --- |
| `AwcmsHostBridgeModule.ets` | `LynxModule` named `AwcmsHostBridge`, plus the pure `HostBridgeDispatcher` and the `openLink`/`startAbility` link opener |
| `HuksSecureStore.ets` | AES-256-GCM with a HUKS key; ciphertext in `@kit.ArkData` Preferences |
| `AwcmsLynxHost.ets` | `LynxEnv` init, template fetcher, `AwcmsLynxView` component (globalProps via `MetaData`), deep-link forwarding |
| `oh-package.json5.snippet` | `@lynx/*` dependencies |

Derived from `lynx-family/integrating-lynx-demo-projects` `harmony/HarmonyEmptyProject` (Apache-2.0).
Build settings from the sample: `targetSdkVersion`/`compatibleSdkVersion` `6.0.0(20)`, `runtimeOS: HarmonyOS`,
`deviceTypes: phone, tablet, 2in1`, a stub `src/main/cpp/CMakeLists.txt` (needed to ship `libc++_shared.so`),
`ohos.permission.INTERNET`.

## 1. Wire it in

`EntryAbility.ets` (sample + our init):

```ts
import { AbilityConstant, UIAbility, Want } from '@kit.AbilityKit';
import { window } from '@kit.ArkUI';
import { AwcmsLynxHost } from '../lynx/AwcmsLynxHost';

export default class EntryAbility extends UIAbility {
  onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {
    AwcmsLynxHost.init(this.context);
    AwcmsLynxHost.handleWant(want);          // cold-start deep link
  }
  onNewWant(want: Want, launchParam: AbilityConstant.LaunchParam): void {
    AwcmsLynxHost.handleWant(want);          // deep link while running
  }
  onWindowStageCreate(windowStage: window.WindowStage): void {
    windowStage.loadContent('pages/Index');
  }
}
```

`pages/Index.ets`:

```ts
import { AwcmsLynxView, AwcmsRuntimeConfig } from '../lynx/AwcmsLynxHost';

function buildConfig(): AwcmsRuntimeConfig {
  const config: AwcmsRuntimeConfig = new AwcmsRuntimeConfig();
  config.backend = 'awcms-one';
  config.apiBaseUrl = 'https://cms.example.id'; // per build flavour / hvigor build mode
  config.locale = 'id';
  config.environment = 'production';
  return config;
}

@Entry
@Component
struct Index {
  build() {
    AwcmsLynxView({ config: buildConfig() })
  }
}
```

Copy `provider/ExampleGenericResourceFetcher.ets` (and its `@ohos/imageknife` dependency) from the sample
unchanged; `AwcmsLynxHost.ets` imports it.

Resources: copy `apps/mobile/dist/main.lynx.bundle` to `entry/src/main/resources/rawfile/main.lynx.bundle`.

## 2. Bundle loading

* Release: packaged rawfile only. `AwcmsTemplateResourceFetcher` rejects `http(s)` URLs unless
  `BuildProfile.DEBUG` (generated by hvigor; true in debug builds), validates the name, and
  `fetchSSRData` is refused outright.
* Debug: `bun run --cwd apps/mobile dev`, then set `bundle` on `AwcmsLynxView` to the dev-server URL.
* Cleartext HTTP to a LAN dev server is blocked by default; configure the app's network security
  config for the dev machine in **debug builds only**. VERIFY the exact profile file and
  `module.json5` metadata name in Huawei's "Network security configuration" documentation; the
  rule of thumb is the same as on the other platforms: never enable cleartext globally in release.

## 3. Devtool in debug builds

The sample registers `LynxDevToolService` in `EntryAbility.onCreate` and lists `@lynx/lynx_devtool`
under `buildOption.arkOptions.runtimeOnly.packages`. Keep that in a debug-only code path / build
mode so release carries no devtool classes:

```ts
if (BuildProfile.DEBUG) {
  LynxServiceCenter.registerService(LynxServiceType.DevTool, LynxDevToolService.instance);
}
```

(Importing `@lynx/lynx_devtool_service` makes it a release dependency too; if that matters, split
it into a separate hvigor build target or `ohosTest`-style module — VERIFY what the current hvigor version allows.)

## 4. Secure storage

HUKS AES-256-GCM key (alias `awcms-lynx-aes-gcm-v1`, non-exportable) encrypts each value; the
Preferences file `awcms_lynx_secure` holds `v1.` + Base64(nonce || ciphertext || tag). The storage key is the
GCM associated data. See the header of `HuksSecureStore.ets` for why this is preferred to the Asset Store
Kit for 16 KiB values, and what happens when the HUKS key disappears (entry dropped, reads null).

If the app enables HarmonyOS backup (`EntryBackupAbility`, `backup_config.json`), exclude the Preferences
file or accept that restored ciphertext is dead weight: the HUKS key does not travel with a backup.

## 5. Push

AWCMS has no push transport for Huawei Push Kit, and FCM is generally unavailable on HarmonyOS NEXT
devices. Until a backend transport exists, push is not supported on this host; do not fake an FCM token.
See `../README.md`.

## 6. Unit-testing the contract

`HostBridgeDispatcher` has no Lynx dependency: in a hypium test (`entry/src/test/*.test.ets`) construct it with an
in-memory `SecureStore` and a recording `LinkOpener`, and replay `../contract-test-vectors.json`. Run the same vectors
once more on a device against `HuksSecureStore` (HUKS needs a real runtime).

## VERIFY list (this directory)

1. Exported type name of the `modules` map values (`AwcmsLynxHost.ets`, `ModuleOptions` is a placeholder).
2. `LynxView` prop spelling `metadata` vs `metaData`.
3. Log-service registration API (`LynxBaseServiceCenter` in the sample vs `LynxServiceCenter` in the guide).
4. `@lynx/lynx` version published on ohpm (4.0.0 per guide; 4.1.0 elsewhere).
5. Whether wrong JS argument types reach `call` or are rejected by Lynx; regular vs `@Sendable` module latency.
6. HUKS AES-GCM tag layout (`HUKS_TAG_AE_TAG`), the error code for tag mismatch, and the per-call input size limit.
7. Asset Store Kit secret size limit (justifies not using it).
8. `UIAbilityContext.openLink(url, { appLinkingOnly: false })` behaviour; `getUIContext().getHostContext()` availability.
9. Cleartext/network-security configuration file for debug builds.
10. Hosting app version string in `LynxEnv.setAppInfo` (hard-coded `0.0.1` placeholder).
